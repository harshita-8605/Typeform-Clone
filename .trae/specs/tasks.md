## Task 2: Database Schema & Models (Forms, Questions, Responses, Answers)
- **Status**: `pending`
- **Priority**: high
- **Depends On**: Task 1
- **Description**:
  - Design and implement SQLAlchemy models:
    - `forms`: id, title, slug (unique), status (draft|published), created_at, updated_at, theme_json (nullable), thank_you_text (nullable).
    - `questions`: id, form_id FK to forms (cascade delete), order_index integer, type (short_text|long_text|multiple_choice|dropdown|email|number|yes_no|rating), title text, description text, required boolean, options_json (nullable — for MC/dropdown choices array; for rating: {max: 5} etc.).

    - `answers`: id, response_id FK (cascade), question_id FK (set null or cascade), value_text (nullable), value_number (nullable), value_boolean (nullable), value_json (nullable fallback). Composite uniqueness on (response_id, question_id).
  - Proper indexes on FK columns; unique index on forms.slug; ordering index on questions.(form_id, order_index).
  - `Base.metadata.create_all(engine)` called on startup OR Alembic single migration.
- **Acceptance Criteria Addressed**: AC-1, AC-4, AC-6, AC-10; NFR-4, NFR-10

## Task 3: Backend API Endpoints — Forms CRUD + Questions
- **Status**: `pending`
- **Priority**: high
- **Depends On**: Task 2
- **Description**:
  - Implement `app/routers/forms.py`:
    - `GET /api/forms` — list all forms (title, slug, status, updated_at, response_count via subquery).
    - `POST /api/forms` — create new form (title optional; default "Untitled form"). Returns form with id.
    - `GET /api/forms/{form_id}` — full form with nested questions array ordered by order_index.
    - `PATCH /api/forms/{form_id}` — rename title, update status.
    - `POST /api/forms/{form_id}/duplicate` — clone form + questions (new slug, new ids; returns new form).
    - `DELETE /api/forms/{form_id}` — delete.
    - `POST /api/forms/{form_id}/publish` — set status=published, regenerate slug if missing; return shareable slug.
    - `POST /api/forms/{form_id}/unpublish` — revert to draft.
    - `PUT /api/forms/{form_id}/questions` — upsert full question list (accepts array with client-order; updates/creates/deletes to match — idempotent). For simpler first version, allow:
      - `POST /api/forms/{form_id}/questions` — add single question (appends with max order+1).
      - `PATCH /api/forms/{form_id}/questions/{q_id}` — edit question.
      - `DELETE /api/forms/{form_id}/questions/{q_id}` — remove; re-serialize order_index.
      - `POST /api/forms/{form_id}/questions/reorder` — accepts ordered list of question IDs; updates order_index.
  - Pydantic schemas for request/response bodies; appropriate 404s.
- **Acceptance Criteria Addressed**: FR-1, FR-2; AC-1, AC-4, AC-6; NFR-5, NFR-10
- **Test Requirements**:
  - `rule` TR-3.1: Create form → add question → list questions → reorder → edit → delete all in curl chain; each call returns 2xx and the final list state matches expected. Evidence: copy-pasteable curl transcript.
  - `rule` TR-3.2: Publish a draft form returns 200 with non-empty `slug`; second publish is idempotent. Evidence: curl output.
  - `rule` TR-3.3: Duplicate endpoint duplicates questions (count matches original). Evidence: before/after question counts in JSON.
- **Notes**: Prefer the "PUT full question list" upsert pattern because it simplifies the builder's save flow; still add single-question endpoints if easier.

## Task 4: Backend API Endpoints — Public Respondent Flow + Responses + Answers
- **Status**: `pending`
- **Priority**: high
- **Depends On**: Task 3
- **Description**:
  - `GET /api/public/forms/{slug}` — return public form data (title, questions ordered — omit internal creator-only fields; 404 if status != published). No auth needed.
  - `POST /api/public/forms/{slug}/responses` — submit response:
    - Accept JSON body `{ answers: [{ question_id: int, value: ... }], meta?: {...} }`.
    - Validate server-side: each required question must have a value; email type regex; number type numeric; rating in range.
    - Return 422 with field-level errors on invalid; else 201 with `response_id` + `thank_you_text`.
  - `GET /api/forms/{form_id}/responses` — list responses (creator; paginate optional) with timestamp, meta, answer count.
  - `GET /api/forms/{form_id}/responses/{response_id}` — single response detail with all answers joined.
  - `GET /api/forms/{form_id}/summary` — per-question summary stats: for MC/dropdown return counts per option; for rating/number return avg/min/max; for yes/no true/false counts; for text count non-empty + avg length.
- **Acceptance Criteria Addressed**: FR-3, FR-4; AC-2, AC-3, AC-5; NFR-4, NFR-5, NFR-6
- **Test Requirements**:
  - `rule` TR-4.1: Submitting required-missing response returns 422 with error referencing the required question. Evidence: 422 response JSON.
  - `rule` TR-4.2: Submitting invalid email returns 422 email error; valid email submission returns 201 with response_id. Evidence: both curl responses.
  - `rule` TR-4.3: Summary endpoint returns correct MC counts for 2 seeded responses. Evidence: summary JSON output compared to DB answer rows.
  - `rule` TR-4.4: Public form endpoint works without auth header, 200 OK; non-published returns 404. Evidence: curl of slug before/after publish.
- **Notes**: Add email regex `^[^\s@]+@[^\s@]+\.[^\s@]+$` as a util.
